# Internationalization

The public site uses `/en` and `/pt` URLs. Portuguese copy uses European Portuguese. URLs without a language prefix redirect to English, independently of browser language. The header language selector preserves the page, query string, and fragment. Payload admin, API endpoints, preview handlers, and static assets keep their existing URLs.

## Fresh database setup

The previous migrations have been removed. Generate and review a new initial migration after resetting the local database. Run from `web/`:

```sh
# Destructive: removes this project's local Postgres data.
docker compose stop db
docker compose rm -f db
docker volume rm websyte_postgres_data

docker compose up -d db mail
pnpm migrate:create initial
# Review and accept any prompts and inspect the generated migration.
pnpm migrate
pnpm generate:types
pnpm generate:importmap
pnpm dev
```

`pnpm dev` creates the contact form and development sample content. Open `/admin` to create a new administrator. The database volume reset was not performed by Codex because its deletion permission was declined.

## Translation ownership

- `src/i18n/config.ts`: supported locales and the shared default locale.
- `src/i18n/messages/en.json` and `pt.json`: UI copy, accessibility labels, form errors, and metadata for code-owned pages.
- Payload's locale selector: titles, rich text, project summaries, navigation labels, media alt text/captions, SEO fields, and form labels/messages.
- Slugs, relationships, block order, form field names, option values, and technical identifiers are shared across languages.
- Payload admin interface language is independent of content language.

The contact form uses the stable `formKey: contact` identifier. Its English and Portuguese content is seeded when it is first created; subsequent development starts retain editorial changes.

## Fallback and search engines

CMS fields fall back to English when a Portuguese value is missing. Pages and posts have a **Translated Locales** field: only mark a language after reviewing the complete translation. This controls sitemap entries and language alternates. Fallback-only detail pages are served with `noindex, follow`. This field is an editorial readiness flag, not separate per-language draft/publish status: Payload publication status remains shared.

The code-owned homepage and archive UI are translated in both languages; their CMS listings can include English fallback content. Search results are not indexed by search engines.

Queries pass a locale explicitly; persistent content caches include locale in their keys. Content changes invalidate both languages so shared fields and English fallback changes remain visible. Preview URLs use the language selected in Payload. The search plugin indexes localized fields; use its Reindex action after bulk imports or changes that bypass normal document hooks.

## Checks

```sh
pnpm exec next typegen
pnpm exec tsc --noEmit
pnpm exec vitest run tests/int/i18n.int.spec.ts
pnpm build
pnpm exec playwright test tests/e2e/frontend.e2e.spec.ts
```

The build and browser tests require the migrated database. The i18n tests do not require Postgres.
